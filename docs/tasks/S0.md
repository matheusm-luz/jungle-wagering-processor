# S0 — Scaffold and harness

**Goal:** a NestJS application on Bun that boots against real PostgreSQL and LocalStack through Docker Compose, answers `/health/live` and `/health/ready`, logs JSON with a correlation id, and has every check script and the migration runner that the later slices build on.

Requirements: R-01, R-02, R-03 (runner only; the schema is S2), R-50, R-60 (logger only; the leak audit is S11). Decisions: ADR-07, ADR-09, ADR-13.

## Subtle points

- **Transaction boundary, lock, idempotency, ack, outbox:** not touched; no table exists yet.
- **Migrations are a one-shot step, never run at application boot.** Three instances booting together would race on the same DDL. In Compose the `app` service waits for `migrate` to exit with 0.
- **Readiness is bounded.** Each dependency check has its own timeout, so a hung PostgreSQL or SQS makes `/health/ready` answer 503 instead of hanging.
- **Liveness never touches a dependency.** Otherwise a PostgreSQL outage would make the orchestrator kill healthy processes.
- **Logging.** Log fields are flat primitives, and environment errors print variable names only: `DATABASE_URL` carries a password.
- **Ledger invariant.** The rule "every integration test ends by asserting the ledger invariant" cannot apply here: `wallets` and `wallet_ledger_entries` are created in S2. The shared assertion helper is introduced with the first test that writes a wallet (S3).
- **Test database.** The suites use their own database, `wagering_test`, so they never touch the data of a running `app` service.
