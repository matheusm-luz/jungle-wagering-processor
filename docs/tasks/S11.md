# S11 — Observability and CI

**Goal:** every instance exposes the seven metrics of statement §12 on `GET /metrics`, each one moving when its event happens; a log-capture test drives every path and finds no financial payload in any line; a GitHub Actions workflow runs the same checks as `/verify`.

Requirements: R-60 (payload-leak audit), R-61. Decisions: ADR-14, from the decisions below.

## Subtle points

- **Transaction boundary.** Counters move after the use case returns, so a rolled-back transaction counts no status; the lock-conflict counter moves on the rollback itself. Gauges read at scrape time open their own read, never inside a business transaction.
- **Lock.** Lock conflicts are the 55P03 of `DATABASE_LOCK_TIMEOUT_MS` (ADR-01), seen in the unit of work, so HTTP, SQS and the worker are counted in one place.
- **Idempotency.** A replay and an inbox duplicate are counted as duplicates, never as new transactions.
- **Ack.** Not touched.
- **Outbox.** The lag is the age of the oldest unpublished row; it is the same for every instance (one database), so a scraper takes the maximum, not the sum.

## Decisions (Matheus, 14 Nov)

- **Q1 — Exposition: (b) `prom-client`.** The de-facto library, pinned at 15.1.3. Rejected: hand-written text format (no dependency, but a histogram and escaping to maintain and test); a JSON endpoint (no scraper reads it). Default process metrics stay off: not required, and their event-loop collector depends on `perf_hooks` support under Bun.
- **Q2 — Gauges computed at scrape: (a).** `now() - min(occurred_at)` over unpublished rows, the pending count and the highest `attempts` (S10 m3), and the DLQ depth, `ApproximateNumberOfMessages` (where the redrive policy's moves land) plus `ApproximateNumberOfMessagesNotVisible` (DLQ messages someone is reading), added while implementing. Sees a stopped publisher; costs one query and one SQS call per scrape, two on the first (the queue URL is then cached). Rejected: publish delay measured by the publisher and the consumer's dead-letter counter only.
- **Q3 — Lock conflicts: (b).** The 55P03 counter and a histogram of the wallet-lock wait. Rejected: timeouts only.
- **Q4 — Outcomes counted at the edges: (a).** Controller, consumer and worker, as S8 counts divergences; no application port. Rejected: a port called by the two use cases.

## Notes from implementation

- **Test order.** T1 failed on the missing families, T2 on a 404, T3 on counters at 0, T5 and the outbox case of T4 on counters at 0; each passed after its code. The HTTP-duplicate, DLQ, lag and pending-reference-retry cases passed on their first run, because T2 (gauges) and T3 (edge counting) already covered them.
- **Log audit.** It passed on its first run: no leak to fix. Mutation: an amount added to the request's log context makes it fail on the access line. It also drives a 500 (the provider's settlement account held `FOR UPDATE`, so the ledger insert's foreign-key check times out); MikroORM 7's `DriverException` message is PostgreSQL's (`canceling statement due to lock timeout`) without the SQL or its parameters. The `reason` of a dead-lettered validation error names the field path and the rule, never the value.
- **Lock conflicts.** `lock_conflicts_total` counts every 55P03 in the unit of work, not only wallet locks: the foreign-key wait above is one. The wallet-lock histogram times only `wallets.lock`.
- **Constructors.** `MikroOrmUnitOfWork`, `OutboxPublisher` and `PendingReferenceWorker` take `Metrics`; the tests that build them directly pass `new Metrics()`.
- **Not done.** Default process metrics (Q1). A timeout on the scrape-time reads (ADR-14, known limitations). The CI workflow has not run on GitHub: only its YAML was parsed locally.

## Independent review (14 Nov)

The `invariant-reviewer` found no blocker and no risk to the financial invariants; one major and eight minors. Fixed in a second commit at Matheus's request: M1, m2, m4, m5, m6, m7, m8. m3 is documented in ADR-14; m1 stays with S12.

- **M1 fixed.** A gauge whose read failed reports `NaN`, and `toBe(NaN + 1)` holds against `NaN` (`Object.is`), so the DLQ-depth assertion passed with the gauge broken. `metricValue` now throws on a `NaN` sample. Mutation: `dlqDepth` made to throw → the case passed before the fix and fails after it.
- **m1 deferred.** Scrape-time reads have no timeout and share the pool of the financial path; already a known limitation, for S12.
- **m2 fixed.** `outbox_lag_seconds` floored at 0: `occurred_at` is the instance's clock, `now()` the database's. Test "an event stamped by an instance whose clock runs ahead of the database shows a lag of 0, never negative", seen failing first (−29.99).
- **m3 accepted.** `sqs_dead_lettered_total` counts twice when the delete after a dead-letter fails; no financial effect; ADR-14.
- **m4 fixed.** The audit now also drives an SQS transient retry (wallet held past the lock timeout) and a message for an unknown wallet, checks forbidden keys at any depth, and its name lists what it drives; the publisher failures, the reconciliation divergence and a failed metric read are named as not driven.
- **m5 fixed.** The worker case waits for its own REFUND's `reference_attempts` and checks that the worker logged that row's resolution, so another row of the shared database cannot satisfy it.
- **m6 fixed.** "a BET sent over HTTP and then over SQS with the same key is a replay" now asserts one SQS duplicate and no SQS transaction. Mutation: the replay branch removed → it fails.
- **m7 fixed.** Q2, T2, T6 and ADR-14 match the code and the test names; the ADR no longer claims the not-visible count is what shows the redrives.
- **m8 fixed.** The CI workflow declares `permissions: contents: read`.

## First CI run (PR #11, 14 Nov)

The CI workflow failed its first run on `test:concurrency`: "committed, then the process dies; … another process publishes every event once" received one event of another wallet. Every check before it was green. Cause: spawned processes ran the pending-reference worker with its defaults over the shared suite database; a REFUND left waiting by an integration suite (the orphan reversals of S4, S7, S8 and now S11 tests) had passed 10 attempts, a process of that file rejected it, and the survivor published its `WagerTransactionRejected` to the file's test topic. Locally the timing hid it. Reproduced locally by leaving one such REFUND due before the file (the same case failed with one extra event id), then fixed at the root: the `test` service idles the worker (`PENDING_REFERENCE_POLL_INTERVAL_MS=1000000000`), as it already idles the publisher; `wallet-races` turns it on for its processes. The same reproduction then passes. No assertion was changed.
