## Subtle points

This slice changes no money path. T2 adds a check before the transaction opens; T6 only drives the service.

- **Transaction boundary, lock, idempotency, ack, outbox.** Unchanged; the README must state the client-visible consequences correctly: a 503 is safe to resend with the same key (nothing committed, or a replay if the connection dropped during `COMMIT`); a `POST /wallets` resend after a lost 201 is 409 (L-19); a 202 is resolved by the worker, and the provider learns the outcome from the event or by querying; SQS messages are acked only after commit; events reach subscribers at least once, ordered by `walletVersion`, deduplicated by `eventId`.
- **T2.** The identity check runs before `BEGIN`, so a refused request takes no lock and writes nothing, like a 400. It is not part of the payload hash: a replay by another caller is refused before the lookup, which is what a real IdP needs. A global guard runs before every controller, health included; the no-op must change no status code, which the existing integration suites prove by staying green.
- **T6.** The load test must not weaken any check: it reports, and the run fails only if the warm-up cannot empty the outbox, the SQS messages are not all applied, or the ledger invariant fails.
