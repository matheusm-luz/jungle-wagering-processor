# S6 — Reversals

**Goal:** `REFUND` and `ROLLBACK` (and the optional reference of `WIN` and `LOSS`) resolve their reference by provider + external id under the wallet lock, check ownership, kind, status, amount and single reversal, and apply or reject with the failure codes of ARCHITECTURE §6.

Requirements: R-31 (reference of a `WIN`), R-33, R-34, R-35, R-36, R-37, R-38 (reversal rejections), R-41, R-42, and the reversal parts of R-28 and R-62. Decisions: ADR-01 (one wallet lock covers the reference, same-wallet foreign key), ADR-03 (the reference is in the hash), ADR-06, ADR-12 (reversals post against the provider's settlement account), L-01, L-09, L-10, L-18.

## Subtle points

- **Lock.** The reference is read after `SELECT … FOR UPDATE` on the wallet. A reference of the same wallet is protected by that lock, and so is the "already reversed" lookup: two reversals of one `BET` are serialised, so the second one sees the first. A reference of another wallet is only read, never written, and ends in `REFERENCE_MISMATCH`.
- **Backstop.** `wager_transactions_single_reversal` cannot fire under the lock. If it does, it is a bug, so it stays a 500 rather than an answer.
- **Rejection keeps no reference id.** The composite foreign key `(reference_transaction_id, wallet_id)` would refuse a reference of another wallet, so a rejected row stores only the declared external id (S1 note in `docs/PROGRESS.md`).
- **Idempotency.** `referenceExternalTransactionId` is part of the hash, so the same key with another reference is 409.
- **Transaction boundary, outbox.** Unchanged from S4: transaction, entry, wallet and events in one `UnitOfWork.run`.

## Decisions (Matheus, 13 Nov)

- **Q1 A missing reference before S7.** (a): the final behaviour now. A reference that does not exist, or that is itself `PENDING_REFERENCE` (L-10), persists `PENDING_REFERENCE`, due at once, and answers 202 with the observed balance. S7 adds the event, the worker and exhaustion without changing these tests. Rejected: a provisional `422 REFERENCE_NOT_FOUND`.
- **Q2 The reference of `WIN` and `LOSS` (L-09).** The same ownership checks, kind `BET`, status `PROCESSED`; no amount check, and a `BET` that was refunded can still be referenced by a `WIN` (documented limitation, consistent with a `WIN` without a reference needing no `BET`). Rejected: blocking a reversed `BET` with `REFERENCE_ALREADY_REVERSED`.
